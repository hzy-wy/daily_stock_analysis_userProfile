# 持仓截图导入

持仓页的“券商交易截图识别”用于把券商 App 中逐笔展示的买卖记录转换成持仓账本事件。它采用“识别预览 → 人工核对 → 确认导入”两阶段流程，不会在上传图片后直接写入数据库。

## 使用步骤

1. 在“账户视图”中选择一个具体账户；“全部账户”不能作为导入目标。
2. 选择 JPEG、PNG、WebP 或 GIF 图片，单张图片不超过 5 MB。
3. 点击“识别并预览”，等待 Vision 模型返回逐笔交易。
4. 核对并按需修改日期、证券代码、名称、方向、数量、成交价、手续费、税费和币种；可删除误识别行。
5. 点击“确认导入”，页面会显示成功、重复和失败笔数，并刷新当前账户的快照与事件列表。

配置要求：`VISION_MODEL`、`OPENAI_VISION_MODEL` 或主 `LITELLM_MODEL` 中至少有一个指向支持图片输入的模型，并为相应 provider 配置有效 API Key。Hermes route 尚未验证 Vision 输入，不能作为该功能的 `VISION_MODEL`。

## 识别与入账边界

- 仅提取带有日期、买卖方向、数量和价格的逐笔交易。“买入/建仓”归一为 `buy`，“卖出/清仓”归一为 `sell`，卖出数量统一保存为正数。
- 截图有证券代码时直接校验并规范化；像券商持仓详情页一样只显示证券名称时，系统只接受本地股票索引中能够精确、唯一反查到代码的名称。无法唯一匹配时跳过该行，不让模型凭知识猜代码。
- 浮动盈亏、当日参考盈亏、实现盈亏、市值、总资产、持仓数量、仓位和行情价格不会作为交易写入。
- 截图没有明确列出费用时，手续费和税费为 `0`，预览行会提示人工核对；系统不会从右侧红蓝盈亏数字推断费用。
- 同一交易日按“买入 → 卖出”顺序提交，避免只有日期、没有成交时刻的截图因展示顺序触发临时超卖。
- 同一张原始图片重复提交时，以图片哈希、原始行序号和用户最终确认的交易字段生成去重键。不同截图即使包含同一交易，也可能需要用户自行删除重复记录。
- 任一行失败不会回滚已经成功写入的其他行；响应会分别返回 `inserted_count`、`duplicate_count`、`failed_count` 和错误摘要。

## 隐私与准确性

图片会发送给你配置的 Vision 模型服务商。上传前应遮盖与交易识别无关的账户号码、姓名、身份证明、联系方式和资产总额等敏感信息。

OCR/多模态识别可能读错小数点、日期、代码或把相邻行拼接，因此确认按钮前的可编辑预览是强制安全边界。请以券商交割单或交易流水为最终依据；截图识别结果不应替代券商原始凭证。

## API 契约

- `POST /api/v1/portfolio/imports/image/parse`：`multipart/form-data` 上传 `file`，返回 `source_hash`、`records[]` 和 `warnings[]`，不写入账本。
- `POST /api/v1/portfolio/imports/image/commit`：JSON 提交 `account_id`、`source_hash`、`records[]` 和可选 `dry_run`，只写入用户确认后的内容。

如果识别接口提示未配置 Vision API，先检查模型名称与对应 API Key；如果提示图片类型或内容不匹配，确认浏览器上传的文件扩展名、MIME 类型和实际文件内容一致。
